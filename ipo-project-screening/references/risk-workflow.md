# 单企业项目风险预核查流程

适用于 `risk_review` 企业或用户指定的单企业核查。该流程用于预研与整改规划，不能替代保荐、法律、审计、税务等专业结论。

## 建立项目基线

先记录：用户提供的拟申报市场/板块、核查期间、材料及取得日期、风险数据覆盖、用户指定的重要性口径、核查责任人。没有明确授权时，不补充板块规则、财务门槛或重要性水平。

## 核查模块

| 模块 | 关注重点 | 结论前通常所需材料/程序 |
| --- | --- | --- |
| M1 主体资格 | 设立、出资、持续经营 | 登记、验资、主体历史 |
| M2 股权与控制权 | 股权清晰、实控人、代持、协议 | 股东名册、沿革、协议和控制权图谱 |
| M3 财务真实性 | 收入、毛利、应收、存货、资金流水 | 审计报表、账簿、合同、发货/验收和银行资料 |
| M4 关联交易与同业竞争 | 必要性、公允性、利益输送 | 关联方清单、交易明细、定价和合同 |
| M5 治理与内控 | 三会、关键控制、内控缺陷 | 章程、会议材料、内控测试和整改记录 |
| M6 行业与持续经营 | 客户供应商集中度、订单、产能 | 客户供应商、订单、现场及行业资料 |
| M7 募投与扩产项目 | 可行性、产能消化、备案环评 | 项目方案、订单、用地、备案和环评 |
| M8 法律合规 | 许可、土地环保、社保、知识产权、诉讼税务 | 证照、公开记录、法律及专项核验 |
| M9 披露一致性 | 文件勾稽和重大事项完整性 | 申报材料草稿、财务、合同和重大事项清单 |
| M10 板块差异 | 已明确板块的发行/披露差异 | 用户提供的现行规则和项目事实 |

## 交叉核验与第三方程序

仅当资料允许时，建议而非声称已完成：收入与产能/库存/交付/验收勾稽，采购与应付/现金流勾稽，利润与现金流勾稽，函证、访谈、现场走访、银行/法律/IP/税务/环保/信用核查。存在相关字段不等于程序已经执行。

## 风险记录和分级

除非用户提供足够事实及项目认可的标准，否则风险状态用 `unresolved`，而不是断言重大/重要/一般。每个发现必须区分其可能涉及的发行条件、财务真实性或披露影响，并记录证据/底稿编号或字段路径、所需程序、资料、责任人、整改状态和复核条件。未完成专业核验前，不得判断风险可整改。
